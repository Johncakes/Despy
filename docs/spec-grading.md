# 평가 기준 (Grading) — 쉽게 보는 채점 모델

> 학생 제출물을 어떻게 0~100점으로 바꾸는가. 합의된 **이진(맞/틀) 2축** 모델.
>
> **상태**: 설계 확정(2026-06-25). 구현은 프로덕션 v1(인증·관리자·DB) 커밋 후.
> 현재 코드는 아직 구 루브릭 모델(항목별 만점·레벨·가중합)이며, 이 문서의 모델로 단순화 예정.

---

## 한 문장 요약

점수 = **"테스트 몇 개 통과했나"** 와 **"교수가 낸 확인 질문에 코드가 맞았나"** 를
교수가 정한 비중으로 섞은 **0~100점**.

---

## 두 개의 축

시험을 두 부분으로 나눈다고 보면 됩니다.

### 축 A. 규칙 기반 (자동 테스트)
- **무엇**: 미리 작성된 vitest 테스트를 학생 코드에 돌린다.
- **채점**: 각 테스트는 **통과 / 실패** 둘 중 하나. 기계가 실행해 판정 → 객관적이고 매번 같은 결과.
- **점수**: `통과한 테스트 수 ÷ 전체 테스트 수`
- **예**: 8개 중 6개 통과 → 75%

### 축 B. AI 이진 체크 (교수가 낸 질문)
- **무엇**: 교수가 "이런 걸 확인해줘"라고 **질문 목록**을 적어둔다.
  - 예) "장바구니가 비었을 때 오류 없이 처리하는가?"
  - 예) "POST /todos가 201과 생성된 항목을 반환하는가?"
- **채점**: AI가 코드를 읽고 각 질문에 **맞음 / 틀림** 둘 중 하나로만 답한다. (부분 점수 없음)
- **점수**: `맞은 질문 수 ÷ 전체 질문 수`
- **예**: 4개 중 3개 맞음 → 75%

> **왜 이진(맞/틀)이냐**: "7점이냐 8점이냐" 같은 애매한 판단을 없애기 위해서다.
> 기준이 명확하고, 점수를 두고 우기기 어렵다. 이게 이 채점 모델의 핵심 원칙이다.

---

## 최종 점수 계산

두 축의 비율을 **교수가 정한 비중**으로 섞는다 (비중 합 = 100%).

```
최종점수 = (테스트 통과율 × 테스트 비중) + (체크 통과율 × 체크 비중)   → 0~100점
```

### 계산 예시
| 항목 | 결과 | 비중 | 기여 |
|---|---|---|---|
| 자동 테스트 | 6/8 = 75% | 70% | 52.5 |
| AI 체크 | 3/4 = 75% | 30% | 22.5 |
| **최종** | | | **75점** |

비중은 과제 성격에 맞춰 조절한다. 테스트가 촘촘한 과제는 **테스트 비중↑**,
정성 판단이 중요한 과제는 **체크 비중↑**.

---

## 누가 무엇을 하나

| 역할 | 하는 일 |
|---|---|
| **교수 (출제)** | ① vitest 테스트 작성 · ② AI 확인 질문 목록 작성 · ③ 두 축의 비중 설정 |
| **학생 (풀이)** | AI 도우미를 활용해 코드 작성 → 제출 |
| **시스템 (채점)** | 테스트 실행 + AI가 질문별 맞/틀 판정 → 비중대로 합산해 최종 점수 확정 |

---

## 솔직한 한계

- AI 체크는 코드를 **실행하지 않고 읽어서** 판정한다 → 100% 정확하진 않다(근사).
  그래서 기계가 실제로 실행하는 **객관적인 테스트 축**을 함께 둬 균형을 맞춘다.
- (현재) 자동 테스트는 학생 브라우저(WebContainer)에서 돌린 결과다. 점수 무결성을 위한
  **서버측 재실행**은 후속 과제다.

---

## 알고리즘 문제는?

이미 같은 철학이다. 각 테스트케이스를 AI가 **맞/틀로 판정**한다(통과 수만 집계, 점수 환산 없음).
이번 개편으로 **과제 채점도 알고리즘과 같은 이진 방식으로 통일**된다.
